# WeatherApp (SwiftUI)

Same functionality as the web frontend (`frontend/index.html` +
`backend/app.py`), rebuilt natively in SwiftUI. Visual style is modeled on
Google's Pixel Weather app: full-bleed condition-based gradient background,
big glanceable temperature, horizontal hourly scroll, simple daily list —
rather than the hairline-table/card layout of the web version.

## Status: running on mock data

The real network calls to the Flask backend are written but **commented
out** in `Services/WeatherService.swift` — the app currently runs on
realistic mock data so the UI is usable standalone before the backend is
reachable from a device. Search that file for `LIVE VERSION` to find every
spot to uncomment once you're ready to wire it up, and see the setup note
at the top of that file for the `baseURL` you'll need to change (localhost
only works in the Simulator; a physical device needs your Mac's LAN IP or a
deployed backend URL).

## Setting this up in Xcode

1. File → New → Project → iOS → App. Name it `WeatherApp`, interface
   SwiftUI, language Swift. iOS 16+ deployment target (uses `.task`,
   `.refreshable`, `NavigationStack`-era APIs).
2. Delete the default `ContentView.swift` Xcode generates.
3. Drag the `Models/`, `Services/`, and `Views/` folders (and their
   contents) from this repo into the Xcode project navigator — check
   "Copy items if needed" and add to the WeatherApp target.
4. Replace the generated `WeatherAppApp.swift` with this repo's
   `WeatherApp.swift` (or just point its `WindowGroup` at `ContentView()`
   if you'd rather keep Xcode's autogenerated file).
5. Build and run — should work immediately on mock data, no backend
   required.

## Font

Uses the system font throughout (SwiftUI's default `Font.system(...)`,
which *is* San Francisco on iOS) — no custom font setup needed, unlike the
web version where SF had to be pulled in via the `-apple-system` CSS stack.

## Going live

Once `backend/app.py` is reachable:

1. Set `baseURL` in `WeatherService.swift`.
2. In each of `fetchForecast()`, `fetchDiscussion()`, `fetchAlerts()`,
   delete the `return try await mock...()` line and uncomment the block
   below it.
3. Add `NSAppTransportSecurity` exceptions in `Info.plist` if you're
   pointing at a plain-HTTP local backend during development (iOS blocks
   non-HTTPS requests by default).

## Location picker

Tap the city name at the top of the screen to search for a new location
(via `MKLocalSearchCompleter`, same tech behind Apple Maps' search bar) or
use "Use Current Location" (via CoreLocation). Selecting either triggers a
full reload through `WeatherService.changeLocation(to:)`.

**Required Info.plist entry** for "Use Current Location" to work:

```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>Used to show the weather forecast for your current location.</string>
```

Add this in Xcode under the target's Info tab, or directly in Info.plist —
without it, the app will crash when location access is requested.

Note: in mock mode, changing location updates the displayed city name but
the mock temperature/condition data stays the same regardless — that's
expected until the live NOAA calls are uncommented.
